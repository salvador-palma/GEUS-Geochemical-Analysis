\section{Introduction}
\label{ch:introduction}

Greenland is one of the world's most mineral-rich but least-explored regions. Over decades, the Geological Survey of Denmark and Greenland (GEUS) \parencite{greenland_portal}  has assembled an extensive public database of geochemistry samples, exploration reports, mineral occurrences, intrusions, geological maps, and license boundaries, all accessible through GEUS web services. This data is heterogeneous in coverage, quality, and completeness, which makes it an interesting and realistic setting for applying machine learning.
The aim of this project is to use machine learning to analyse geochemical data from GEUS and explore what can be learned from it. For example, identifying patterns across elements, reconstructing missing measurements, mapping spatial trends, or relating geochemistry to known mineral occurrences. 


\subsection{Research questions}

The project was organized around two major problems:

\begin{description}
    \item[RQ1 --- missing geochemistry.] Given a sample predict an held-out element from the sample's other elements and its spatial neighborhood.
    
    \item[RQ2 --- unexplored regions.] Predict concentrations in an held out geological area rather than at random, avoiding spatial leakage.
\end{description}

This report focuses on \textbf{RQ1}, while setting some ground for the \textbf{RQ2}.

\subsection{Contributions}

This project applies one identical pipeline to two GEUS datasets with different sampling geometries. In this first part, I contribute with the following: 

\begin{description}
    \item [Contrasting different KNN integrations.] Comparing distinct methods of encoding a spatial neighborhood as tabular data, across seven neighborhood sizes.
    \item [Evidence that spatial context is largely redundant.] A strong baseline obtained only by a sample's own geochemistry doesn't gain much with geophysical or spatial information. Some elements are exceptions, however.
    \item [Comparison between hand-built vs learned neighbor aggregation.] Two different graph neural networks (GNN), with distance-aware and unaware edges, are evaluated against the handbuilt KNN encodings.
    
\end{description}

\subsection{Preprocessing}
\label{sec:pipeline}

The preprocessing of data consists on the following six steps:

\begin{enumerate}
    \item \textbf{Mask below-detection values.} non-NaN entries that present negative values are usually interpreted as below-detection limit (BDL). Rather than keeping these values as is, or trying to perform educated approaches, BDL values are treated as NaN.
    
    \item \textbf{Merge analytical columns.} Some columns represent a measurement of the same element but across different laboratories and methods. 
    These different methods differ in detection limits, biases, instruments, etc, even if measured on the same sample for the same element, so they are aggregated by the median as a neutral design choice. 
    This is what makes the Stream Sediment dataset move from 523 columns to 93.
    
    \item \textbf{Merge by sample number.} Similarly to the step above, some rows are repeated across the same extracted sample, but measured by different methods. 
    The aggregation is done in the exact same way: median across the rows depicting the same sample number.
    
    \item \textbf{Log-transform.} After merging both dimensions, the numerical data is $log_{10}$ transformed to follow the natural distribution of geochemistry. 
    An added advantage is that this process diminishes the negative effect of outliers and sentinels.
    
    \item \textbf{Coverage filter.} Element columns measured in fewer than 10 samples are completely dropped from the dataset, as columns with mostly NaN wouldn't add meaningful information for inference. 

    \item \textbf{Splits.} All experiments are done on the very same five-fold cross-validation. As we are still in the context of RQ1, there is no spatial holdout, and the samples are randomized, leading to a perfect 80/20 split in every fold (\Cref{fig:kfoldsplit}).
    
\end{enumerate}

\subsection{Targets and evaluation}
\label{sec:evaluation}

Every element measured in at least \num{1000} samples is a target. Leading to 48 and 71 total targets on Whole Rock and Stream Sediment, respectively.

Each target is predicted from the sample's remaining elements and scored by \Rsq{} over the five random folds. Samples that did not measure the target element are naturally discarded.

Once again, since we are in the context of RQ1, spatial leakage can be a problem due to lack of spatial CV. That is, a model trained on a certain sample can be guessing a sample just a few meters away, which can be considered duplicates in certain perspectives.

\subsection{KNN Encoding}
\label{sec:neighbours}

Neighbor features are built at training time, per fold. This means that a $k$-d tree is fitted on the training samples only, so a test sample never recognizes another test sample as a neighbor, which is a very straightforward method to block data leaks. Additionally, self-matches and co-located neighbors are discarded, meaning that a neighbor is necessarily at a different geographical location, not just a different sample from the same exploration site.

Four different types of encodings are compared. 
With $k$ neighbours and $m$ elements they differ in how much they aggregate (\Cref{tab:encodings}).

\subsection{Geophysical features}
\label{sec:geophysics}
Geochemical neighbors only exist where somebody has already explored. Geophysical grids, on the other hand, are measured everywhere. Therefore, on unexplored ground, they are a motivated input.

Three geophysical attributes were added to each entry of both datasets: Magnetic anomaly, geothermal heat flow, and depth to Moho.

Despite wanting to introduce more geophysical features, I wasn't able to find more grids that properly covered all points in our dataset on the GEUS platform.

\subsection{Models}
\label{sec:models}

Gradient-boosted decision trees remain one of the strongest machine learning methods on tabular data with this size and heterogeneity. The main model is the histogram-based gradient boosting (HGB) implementation in scikit-learn. As a comparison, a simple random forest (RF) and an XGBoost (XGB) model are also run on the same pipeline for the initial experiments, as to check that conclusions are not an artifact of model bias.

\subsection{Graph neural network}
\label{sec:gnnmethod}

A GNN offers a different way to use the sample neighborhood. Rather than aggregating by mean, or enumerating individual values into fixed columns, the relationships and their relevance is learned automatically. 
The graph presents one node per sample, and directed edges to the respective $k$ nearest neighbors. 
So each sample sees the exact same neighborhood in the GNN as it saw in the hand-built version. 
Each edge carries $\log(1+d)$, with $d$ in kilometers. 
The node features are the sample's own elements. 
Since the network cannot consume NaN values, each element has two channels: A value channel where it is zero whenever the original value is NaN; And a presence/absence channel to serve as a flag.

Two different architectures are compared: A GraphSAGE, which is distance-blind by construction, and a graph attention network (GAT), that computes attention weights per edge from the distance, wich is something the previous KNN variants were missing. Other than this structural distinction, both use two message-passing layers of width 64, a skip connection from the node's features to a two layer head, dropout \num{0.1}, and Adam optimizer at learning rate $10^{-2}$ with $10^{-4}$ weight decay. 

GNN experiments were run only on Stream Sediment as it was the only dataset where standalone spatial signal was strong enough to justify a learnt aggregation.

Sweeping $k$ from 1 to 100 (\Cref{fig:ksweep,app:k-sweep}) reveals a pattern: On both datasets, variants A and C mostly plateau at $k \approx 20$, with the exception of the latter one having a steady decrease on Stream Sediment at $k=100$; While variants B and D are consistently negatively affected as $k$ rises. This constant decrease in performance is due to the fact that the dimensionality of the dataset in these variants is directly proportional to $k$. Variant D, the heavier one, has \num{1740} columns at $k=20$, while at $k=100$, it already contains \num{8700}, with the possibility of many of these columns being NaN values. Essentially, even though variants B and D are more detailed about the neighborhood, the models are not capable of using it correctly and end up drowning in information. 

If the reader is wondering about the mismatch between the values of the $k$-sweep and \Cref{tab:variants}, it is because the former is conducted on only the ten most commonly measured elements on each dataset, meaning the measurements can be slightly affected, especially in Stream Sediment, since certain elements can benefit more from neighbor information such as uranium, which is discussed again in \Cref{sec:pathfinders}. What is relevant in this section is the aforementioned pattern that exists regardless of target set and dataset.

\subsection{Relevance of each spatial information feature}
\label{sec:featuresets}

By scoring each feature source on its own and in combination (\Cref{fig:featuresets}) allows us to understand what spatial information is more beneficial. 


\begin{figure}[htbp]
\centering

\label{fig:featuresets}

\paragraph{Sampling geometry affects standalone spatial information}
Every standalone feature type is roughly twice as informative on stream sediment as on whole rock. This is a large difference that could be expected given the different sampling geometries of both datasets (\Cref{fig:samples}).

\paragraph{Sampling geometry does not affect the gain by spatial information.} 
Even with such a different strength in standalone spatial signal, what that information adds to the current baseline is approximately the same: $+0.015$ versus $+0.012$ for neighbors, $+0.008$ versus $+0.009$ for coordinates, $+0.008$ versus $+0.006$ for geophysics. This means that the information ends up being redundant when faced with the strong geochemistry baseline, as a sample's own chemistry is a much stronger predictor than anything else.

\paragraph{Geophysics does not beat location.}
Coordinates mostly outscore geophysics on both datasets, and a combination of the two barely surpasses coordinates by itself ($0.6017$ versus $0.5994$ on stream sediment). Essentially, the geophysics are serving as a proxy of location, encoding \textit{where} a sample is rather than \textit{what} is underneath. A model-independent correlation test also agrees to this result: by comparing the strongest correlation with a geophysical feature to the strongest in easting or northing, geophysics only wins on 27 of 64 ($42\%$) elements of whole rock, and 26 of 81 ($32\%$) on stream sediment. Some of the elements that more strongly resonate with geophysics rather than location can be seen in (\Cref{app:geophysics-vs-location-individual}).



\subsection{Elements with weaker baselines benefit from spatial information more}
\label{sec:difficulty}

All \Rsq{} metrics reported in the results above still make it hard to understand the improvement (or lack of) in different elements. By binning the targets based on their initial baseline score, we can properly verify that the elements with weaker initial scores do benefit more from additional data, especially regarding the surrounding neighborhood (\Cref{fig:difficulty}).


\begin{figure}[htbp]
\centering
\includegraphics[width=0.92\textwidth]{difficulty.png}
\caption[Gain stratified by baseline difficulty]{
Mean improvement over own chemistry, with target elements binned by their baseline \Rsq{} score (\Cref{app:baseline-binning})}
\label{fig:difficulty}
\end{figure}

Despite all the differences in these datasets, such as sample count, spatial extent, co-location rate, or targets, the decay is monotone, and the curves are nearly identical on both. 

Neighbors are worth, on average $+0.0517$ to the eight whole-rock targets with a baseline $< 0.70$ and $0.0484$ on stream sediment, with mean baseline of \num{0.5920} and \num{0.5846}, respectively. However, with a baseline $> 0.95$, the increase in information only contributes $0.0008$ for the three whole-rock targets and $+0.0001$ for stream sediment. 

This result explains why any \Rsq{} metric over such an extended target set can be misleading: Gain from neighbor information under $0.01$ occurs in $40$ out of $48$ ($83\%$) and $50$ out of $71$ ($70\%$) target elements for both datasets, respectively, essentially omitting large gains for the few elements that end up benefiting.

\subsection{Chemical isolation worsens the baseline}
\label{sec:isolation}

In \Cref{sec:difficulty}, I reported on how elements with a weaker baseline tended to benefit more from additional features. However, what exactly leads to a lower baseline still needs to be discussed. As we are dealing with tabular algorithms, by nature, the closest correlations are used as leverage to find the correct approximated values. Likewise, a lack of such close correlation could mean the inability to perform. 
For each element, take the strongest (Spearman) correlation $|\rho|$ it has out of all the elements and call it \emph{companion strength}. Essentially, how good of a proxy the sample already carries for a specific element.

\begin{figure}[htbp]
\centering
\includegraphics[width=0.92\textwidth]{isolation.png}
\caption[Chemical isolation]{Baseline \Rsq{} against companion strength. Area size defines the gain from neighbor integration.}
\label{fig:isolation}
\end{figure}

This so-called companion strength fairly predicts the baseline on both datasets ($r= 0.77$ and $0.76$, respectively)(\Cref{fig:isolation}). 
Splitting the target elements by whether they have any partner above $\rho=0.8$ into \emph{isolated} and \emph{accompanied} elements creates an interesting result shared among both datasets: Accompanied elements have a baseline of $0.8639$ on whole-rock and $0.9200$ on stream sediment, with a neighbor gain of $0.0047$ on both, while isolated elements average $0.7380$ and $0.7822$ with a neighbor gain of $0.0242$ and $0.0253$, respectively. This increase in neighbor gain is between \num{5.2} to \num{5.4} times higher for accompanied than for isolated elements in both datasets, even though the split dimension is different ($25 \text{ out of  }48$ $(52\%)$ and $27 \text{ out of } 71 $ $(38\%)$ isolated), and the target elements differ.

What this exposes is a substitution. The elements at the top-right track each other almost perfectly (Ce--Pr $\rho = 0.995$, Ho--Er $\rho = 0.993$), and have several strong companions that are also accompanied elements. These elements are therefore largely predictable in the absence of the target element, making the neighborhood information unneeded. The elements at the lower-left have no such proxy: On stream sediment, for instance, gold's best companion is iron with $\rho=0.307$, arsenic's is lithium at $\rho = 0.469$, sulfur's is mercury at $\rho=0.517$, and none of these have a partner above $p\ge0.80$ (\Cref{app:companion-strength}). 

Tying together the previous sections, spatial context is worth something where the sample's own chemistry does not have a good proxy for the target.

\subsection{A learned aggregation does not do better}
\label{sec:gnnresults}

\Cref{fig:gnn} compares both graph architectures against KNN-C across the same seven values of $k$, on identical folds. Note that contrary to \Cref{fig:ksweep}, this time the sweep is done over the full target set rather than the ten most measured elements.

\begin{figure}[htbp]
\centering
\includegraphics[width=0.74\textwidth]{gnn.png}
\caption[Graph networks against hand-built neighbor features]{Mean \Rsq{} on stream sediment for
the two graph architectures and the hand-built KNN variant C encoding, across neighborhood size.}
\label{fig:gnn}
\end{figure}

\paragraph{The hand-built encoding wins everywhere.} 
Variant C of the KNN integration is above both networks at all
seven values of $k$, with no crossover at any point. The difference is not significant, however, especially when accounting for the standard deviation bands. Therefore, calling it a win is a big exaggeration. The plateau region that was reported in \Cref{sec:variants} is also similar to the region where the GNNs plateau.

\paragraph{Distance-aware attention does not make a difference} 

The two GNN architectures both follow similar results, with the best configuration being \textsc{SAGE} at $k=20$ (\num{0.8271}). At a low $k$, the two methods discriminate the distance-weighted edges usefully, but as the neighborhood size increases, the difference in performance diminishes almost monotonically. After $k=20$, the same effect that caused variant KNN-D to yield a lower performance seems to be taking action on the GNNs as well, albeit not to the same extent. This is because, just like variants B and D were drowning in information from tracking multiple columns, \textsc{SAGE} and \textsc{GAT} need to keep track of edges in the same manner.
